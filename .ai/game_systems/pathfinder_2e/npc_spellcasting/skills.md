# Submodulo: Pathfinder 2e NPC Spellcasting (Skills & Tech)

**Status: ✅ implementado em 2026-07-13.**

## 1. Stack
* Reuso quase total das funcoes puras ja existentes e testadas em `packages/game-system-pathfinder-2e/src/server/spell-casting/` (`applyPathfinder2eCast`, `applyPathfinder2eRest`, `applyPathfinder2eRefocus`, `buildPathfinder2eCastOptions`, `resolvePathfinder2eSpellResolutionProfile`, `resolvePathfinder2eBasicSaveDamage`) — todas operam sobre `Pathfinder2eCharacterSpellbookData`, um tipo que nao menciona `Character` em nenhum campo. Nenhuma dessas funcoes foi alterada.
* Spellbook de NPC mora direto em `CampaignNpcDefinition.spellbook` (`Json?`), sem tabela nova e sem `revision` (so o Mestre escreve, sem concorrencia otimista entre jogadores como existe para personagem) — `apps/api/src/modules/npc_definitions/routes.ts`.
* Rotas de conjuracao/resolucao de NPC vivem em `apps/api/src/modules/spell_casting/npc-routes.ts` — arquivo **separado** de `spell_casting/routes.ts` (personagem), nao uma generalizacao das rotas existentes.

## 2. Padroes Aplicados
* **Spell DC fixo, nao calculado**: `Pathfinder2eSpellcastingEntry` ganhou um campo aditivo `npcSpellDC?: number` (`packages/game-system-pathfinder-2e/src/server/character-spells/models.ts` e o espelho web em `.../web/character-sheet/spells/types.ts`). Quando presente, a rota de resolucao de NPC usa esse valor direto como Spell DC, sem chamar `calculateSpellDC` — evita contar a base "+10" duas vezes (statblock de monstro ja imprime o DC final).
* **Salvamento de NPC-como-alvo, reuso com atributo re-propositado**: `loadNpcTargetSaveInput` (exportado de `spell_casting/routes.ts`) chama `calculateSavingThrow(statistic, {level: 0, rank: 0, attributeModifier: valorFixoDoStatblock, ruleElements: []})` — devolve exatamente o valor fixo (proficiencia 0 + esse "atributo" + 0 de Rule Engine), sem uma segunda formula.
* **Permissao Mestre-only, nao dono-ou-Mestre**: toda rota de conjuracao/resolucao de NPC usa `getMasterCampaignAccess`/`getNpcDefinitionForMaster` (`npc_definitions/routes.ts`) — nunca a verificacao dono-ou-Mestre usada para personagem.
* **Duplicacao deliberada da resolucao de cena/geometria, nao generalizacao**: `resolveNpcCastSceneContext`/`validateNpcCastPlacement`/`resolveNpcNonAreaCastContext` (`npc-routes.ts`) reimplementam a mesma logica de `resolveCastSceneContext`/`validateCastPlacement`/`resolveNonAreaCastContext` (personagem), mas checando `campaignNpcDefinitionId` em vez de `characterId`. As pecas realmente puras (geometria, formulas de alcance/area) foram **exportadas** de `spell_casting/routes.ts` e reutilizadas (`GEOMETRY_EPSILON`, `isExpectedShapeForArea`, `isWithinSpellRange`, `placementAnchor`, `HEX_SUPPORTED_SPELL_AREA_TYPES`, `targetCountLabel`) — so a orquestracao com queries Prisma foi duplicada. Decisao deliberada: `apps/api/src/modules/**` nao tem cobertura de typecheck nem teste automatizado (item 22.10 do plano canonico), entao alterar as 4 funcoes ja testadas do fluxo de personagem sob pressao de tempo teria risco maior do que duplicar ~150 linhas de geometria ja estavel.
* **`resolveSpellResolutionScene`** (endpoint de resolucao, nao de cast) foi generalizada de verdade — aceita `{kind:'character', characterId} | {kind:'npc', campaignId, definitionId}` e devolve alvos tipados `{source:'CHARACTER', characterId} | {source:'BESTIARY', bestiaryCreatureId}`. Diferente das funcoes de cast, so tinha um unico call site (o handler de `/resolve`), entao generalizar foi mais barato que duplicar.

## 3. Restricoes Tecnicas
* Conjuracao de NPC nao tem ledger `recentCasts` nem checagem de "cast real antes de resolver" (diferente do personagem, `.ai/spell_casting/specs.md` secao 2.1) — aceito porque so o Mestre pode disparar essas rotas, e o Mestre ja tem autoridade total sobre HP de qualquer token via `.ai/combat/specs.md` secao 6.1. Reenviar a mesma requisicao gera uma nova rolagem/consumo — mitigacao e so client-side (nao reenviar).
* `NpcSpellCastPanel` (UI) nao suporta magias com area — mostra erro e nao chama nenhuma rota. Nao ha equivalente de `onRequestAreaPlacement` para NPC nesta rodada.
* Editor de spellbook de NPC (`NpcSpellbookEditorModal`) so cria entradas `category: 'INNATE'` — o backend aceita as outras categorias (mesmo schema de personagem), mas nenhuma UI as expoe. Um spellbook de NPC editado diretamente via API com outra categoria funcionaria mecanicamente (mesmas funcoes puras), so nao ha tela para isso.
* Sem action economy para NPC — debitar `actionsRemaining` de um participante de encontro so funciona hoje para `characterId` (`consumeEncounterActionsForCharacter`); conjurar por NPC nunca debita acoes de encontro, mesmo com encontro ativo.
* Anuncio de conjuracao de NPC vai **so** para o log de batalha (`appendSystemLogToActiveEncounter`), nunca para o chat de campanha — `createAndBroadcastCampaignChatMessage` exige uma `CampaignCharacter` ativa vinculada ao remetente, que um NPC nao tem.

## 4. Limitacoes Conhecidas
* Toda limitacao ja documentada em `.ai/game_systems/pathfinder_2e/resolution/skills.md` se aplica igualmente a conjuradores/alvos NPC (sem ataque de magia, sem salvamento nao-basico, sem dano composto, sem cura, sem alvo de area).
* NPCs nao tem `character_effects` (efeitos ativos) — `ruleElements` de NPC e sempre `[]`, tanto como conjurador (Spell DC) quanto como alvo (salvamento). Bonus/penalidades temporarias em NPC ficam fora de escopo ate que exista um equivalente de efeitos ativos para bestiario.
* Excluir uma `CampaignNpcDefinition` com tokens instanciados retorna erro (o Mestre precisa remover os tokens primeiro) — nao ha "desvincular automaticamente".
